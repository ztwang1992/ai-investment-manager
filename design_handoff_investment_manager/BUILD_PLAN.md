# 开发计划：个人投资管理器 PWA

这份计划写给你自己，边看边做。每个阶段有三部分：
- **目标**：这一步做完能得到什么
- **提示词**：整段复制粘贴给 Claude Code
- **验收**：你自己动手检查的清单

每个阶段都验收通过，再进入下一个阶段。

---

## 开始之前

1. 新建一个空文件夹，比如 `invest-app`，把整个交接包放进去，路径是 `invest-app/design_handoff_investment_manager/`。
2. 把交接包里的 `CLAUDE.md` 复制到 `invest-app/` 根目录。Claude Code 每次启动都会自动读取它。
3. 在 `invest-app/` 里执行 `git init`，然后在 GitHub 上新建一个 private 仓库并关联到这里。
4. 在这个文件夹里打开终端，运行 `claude`。

**常用习惯**
- 每个阶段完成后，都对 Claude Code 说：「提交一个 commit，信息写清楚这个阶段做了什么」。
- 遇到报错，把完整报错原样粘给 Claude Code，不用自己总结。
- 改需求时，先说"不要改 X，只改 Y"。

## 阶段 0 · 可行性验证（约半天）

**目标**：写后端之前，先确认这套方案在国内走得通：自己的域名手机能打开、免费行情源在 Worker 里能用、Supabase 的访问速度可以接受。可以和阶段 1 同时进行，但要在阶段 2 之前做完。

**你要先做**
1. 注册 Cloudflare，安装 wrangler（`npm i -g wrangler`），运行 `wrangler login`。
2. 在腾讯云买一个域名（建议 .com），完成域名实名认证；然后在 Cloudflare 添加这个域名，到腾讯云「域名注册 → 更多 → 修改 DNS 服务器」，填上 Cloudflare 给的两个地址。不需要备案。
3. 在 Supabase 新建项目，区域选 Singapore。

**提示词**
```
做一次可行性验证，代码放在 spikes/ 下，验证完就删：
1. 部署一个最简单的 Worker 和一个静态页面，分别绑定到 api.<我的域名> 和 app.<我的域名>。
2. 在 Worker 里实测候选的免费数据源，每类至少比较两个：
   - 美股 / 美股 ETF（VOO、QQQ）：候选如 Yahoo Finance 非官方接口、Stooq、腾讯行情等
   - A 股 / A 股 ETF（513500、510300、600519）：候选如新浪、腾讯、东方财富的公开行情接口
   - 场外基金净值（050025，要带净值日期）：候选如天天基金的公开接口
   - 汇率 USD/CNY、HKD/CNY：候选如 frankfurter.app 等
   每个源记录：能不能从 Worker 访问、延迟、数据时效、需要的请求头、限流情况。给我一份对比表，并推荐主用和备用方案。
3. 告诉我怎么用手机 4G（不连 Wi-Fi）测试这两个地址和 Supabase 的访问速度。
```

**验收**
- [ ] 手机 4G 能打开 app.<域名> 和 api.<域名>
- [ ] 每类数据都选定了在 Worker 里能稳定访问的主用源和备用源
- [ ] 手机 4G 访问 Supabase 的延迟可以接受

## 阶段 1 · 骨架 + 5 个标签（用示例数据）

**目标**：本地跑起一个手机尺寸的 PWA，5 个标签的界面和原型基本一致，数据暂时写死。这一阶段不接任何后端。

分三步做，每一步验收通过再做下一步。

### 1a · 计算逻辑（纯函数 + 测试）

**提示词**
```
请阅读 design_handoff_investment_manager/README.md 和原型 v5 的脚本部分。
用 Vite + React + TypeScript 初始化项目（这一步只建骨架，不写页面），配好 Vitest。
把原型里的计算逻辑按 README 整理成纯函数，放在 src/domain/，每个都写单元测试：
- 按底层资产合并、槽位占比与偏离（包括「个股合计」、单独设目标的个股、「未定义」资产的两种处理）
- 退休推算、区间收益率
- 增量投入的注水算法、取钱算法
- 由流水推导持仓、现金和净投入本金（规则见 README「流水类型」），以及记一笔时自动补记入金 / 出金
- 校准（存实际份额、总成本不变、份额没变记为「已核对」）和待校准清单
示例数据照搬原型，放在 src/mock/，原型里的持仓转成「期初」流水。src/domain/ 不能引用 React 或浏览器 API。
```

**验收**
- [ ] `npm test` 全部通过
- [ ] 测试里包括：「投入一笔钱」只买不卖、分配合计等于投入金额，钱不够补齐所有候选时被买入的槽位都不超过目标比例；取钱只卖同币种的持仓；买入时现金不足会补记入金
- [ ] 测试里包括：把两台设备的流水打乱合并后，推导出的持仓和按时间顺序记账的结果一致

### 1b · 外壳、设计 token、PWA

**提示词**
```
1. 把 Organic 设计 token（README 里的「设计 Token」一节，以及交接包里的 styles.css）整理成 src/styles/tokens.css，全局引入。
2. 做出手机尺寸的 App 外壳：底部 5 个标签（收益 / 计划 / 持仓 / 记录 / AI 投顾），每个标签页先放占位。
3. 用 vite-plugin-pwa 配好 manifest 和图标占位，支持「添加到主屏幕」。
4. Caprasimo 不含中文字形。给我 2–3 个圆润的中文标题字体候选（要允许网页使用，并且能按需子集化）；我选定之前，中文先回退到系统字体。
完成后告诉我怎么在手机上预览。
```

**验收**
- [ ] 运行 `npm run dev` 后，在手机浏览器里打开局域网地址，5 个标签都能切换，标签栏和原型一致
- [ ] 能「添加到主屏幕」，并以全屏方式打开
- [ ] 选定了中文标题字体

### 1c · 逐页实现

按 收益 → 计划（含「设置组合」和各个底部面板）→ 持仓（含「设置账户」和校准面板）→ 记录（含「记一笔」）→ AI 投顾 的顺序，一次做一页。首次录入引导放到阶段 3。

**提示词**（每页一次，把 <页面> 换成页面名）
```
按原型 v5 实现「<页面>」，包括它的二级页面和底部面板，布局、间距、颜色、文案都以原型为准。
计算全部调用 src/domain/，组件里不写计算；数据用 src/mock/。AI 投顾页这一阶段先用固定回复。
原型里有几处文字被挤到了第二行（比如「组合配置」标题、资金进出列表里的日期），这种不要照抄。
做完后和 screenshots/ 里对应的截图对照，列出差异。
```

**验收**
- [ ] 每个页面都和原型截图对照过，没有明显差异
- [ ] 在手机上把每一页点一遍，展开、切换、底部面板等交互和原型一致

## 阶段 2 · Supabase：登录 + 数据库

**目标**：用邮箱登录，数据存在云端；换一台设备登录，还能看到同样的数据。离线也能记账，联网后自动同步。

**你要先做**：到 Supabase 项目（阶段 0 已新建）的 Settings → API 复制 `Project URL` 和 `anon key`。

**提示词**
```
接入 Supabase。我的 Project URL 和 anon key 会放在 .env.local 里（VITE_SUPABASE_URL、VITE_SUPABASE_ANON_KEY），请把 .env.local 加进 .gitignore。

1. 按 README 的「数据模型」一节，写好 SQL 迁移文件，放在 supabase/migrations/。所有表开启 RLS，策略设为「只能读写自己的数据」；exposures、instruments 的全局预置行例外（见 README）。流水表只允许新增和读取自己的行。
2. 登录方式用邮箱 6 位验证码（OTP），不要用 magic link（原因见 README「技术栈」）。做一个和 Organic 风格一致的登录页，并告诉我怎么配置自定义 SMTP。
3. 按 README「本地优先与同步」一节，把阶段 1 的示例数据换成真实的读写：
   - 手机本地用 IndexedDB 存完整数据（可以用 Dexie），界面直接读本地数据；状态层自选并说明理由
   - 记一笔先写本地、立即显示，同时进入待同步队列；联网后按顺序上传，用流水 id 去重，失败自动重试
   - App 启动、回到前台、网络恢复时，拉取其他设备的新数据
   - 在界面上提示还有几笔待同步（放在哪里、长什么样，先给我看方案）
4. 写一个把示例数据导入我账号的脚本或按钮，方便测试。

请告诉我需要在 Supabase 控制台里手动执行哪些步骤。
```

**验收**
- [ ] 能收到验证码邮件并登录
- [ ] 记一笔后刷新页面，数据还在
- [ ] 在另一个浏览器用同一个邮箱登录，能看到同样的数据
- [ ] 在 Supabase 的 Table Editor 里，每行数据的 user_id 都是你的
- [ ] 断网（飞行模式）后打开 App，能看到上次的数据，也能记一笔，界面立即更新
- [ ] 恢复网络后自动同步，另一台设备刷新后能看到这笔记录
- [ ] 两台设备都离线、各记一笔，联网后两边的持仓一致

## 阶段 3 · 首次录入、记一笔、校准

**目标**：真正可以开始用。从零录入自己的账户和持仓，日常记录买卖、入金出金、校准。

**提示词**
```
按 README 实现以下流程：
1. 首次录入引导（新账号没有任何账户时自动出现），共三步：
   - 选账户
   - 按账户录入持仓和现金；填好但没点添加的那一行，在切换账户或点下一步时要自动加进去
   - 目标组合：按当前持仓比例生成，或暂不设
   - 完成时按 README 写入「期初」流水
2. 「记一笔」四种类型：买入 / 卖出 / 入金 / 出金。现金联动和手续费的规则见 README 的表格。
3. 品种代码 → 底层资产的映射表：在 instruments 表里预置全局数据（user_id 为空，见 README），先覆盖常见的美股 ETF、A 股 ETF、QDII 基金；识别不了时让用户手动选，存为用户自己的品种。
4. 校准面板：总成本不变、平均成本摊薄；份额相同时记为「已核对」。
5. 季度校准提醒：规则见 README；计划页显示「持仓校准」卡片，并提供待校准清单。
6. 「设置组合」里目标组合的查看态 / 编辑态：数字直接输入，合计必须等于 100% 才能保存，超出时报错。另外还有「未定义」资产区块。
7. 记录页的时间、类型筛选和排序。

所有涉及金额的计算都放在 src/domain/ 里，并补充单元测试。
```

**验收**
- [ ] 注册一个新邮箱，从零录完自己真实的全部账户和持仓
- [ ] 持仓页「按底层资产」里，VOO、513500、标普 QDII 合并在「标普 500」下
- [ ] 买入时账户现金正确减少；现金不够时会自动补记入金
- [ ] 校准一条后，计划页的待校准数量减 1
- [ ] 编辑目标组合时，合计填到 110% 会报错，无法保存

## 阶段 4 · 行情、汇率、每日快照（最费时间）

**目标**：价格和汇率自动更新，收益曲线用真实数据画。

**你要先做**：无（Cloudflare 账号、wrangler 和域名在阶段 0 已准备好）。

**提示词**
```
新建一个 Cloudflare Worker（放在 worker/ 目录），作为行情和汇率的中转：
1. 接口：GET /quote?codes=VOO,513500,050025 和 GET /fx（支持 ?date=YYYY-MM-DD 查历史汇率），返回统一格式：{ code, price, currency, asOf, source }。离线记的流水上传前，用 /fx?date= 换成记账当天的实际汇率（见 README「本地优先与同步」）。
2. 数据源用阶段 0 选定的主用 / 备用方案（场外基金是 T-1 净值，要带上净值日期）。主用源失败时自动切到备用源，都失败时返回上次缓存的结果并注明时间。Worker 内部要做抽象，方便以后替换数据源。
3. 用 Cloudflare KV 缓存结果：交易时段 15 分钟，非交易时段 6 小时。
4. 前端冷启动时、以及下拉刷新时，调用这两个接口。
5. 每日快照：用 Worker 的 Cron Trigger，每天北京时间 06:00 为每个用户计算一次总资产、净投入本金、当天的 usd_cny 和各底层资产的市值，写入 snapshots 和 snapshot_items 表，计算复用 src/domain/ 的函数。首次录入完成时也要立即写当天的第一条快照。Worker 访问 Supabase 时使用 service role key，这个 key 只放在 Worker 的 secret 里。
6. 收益页改为读取 snapshots 表来画图；入金 / 出金的圆点来自 transactions 表；「各资产表现」读取 snapshot_items；美元视图按 README「美元视图」一节换算。
```

**验收**
- [ ] 下拉刷新后价格有变化，「已更新」的时间正确
- [ ] 场外基金显示了净值日期
- [ ] 连续运行 3 天后，收益页出现 3 个点
- [ ] 故意把某个数据源地址写错，App 不会崩溃，会显示上次的价格并提示「行情暂不可用」

## 阶段 5 · 再平衡、投入一笔钱、取钱

**目标**：三种调整功能都能用，而且点「按此记录」后会真实写入数据。

**提示词**
```
把阶段 1 写好并测试过的 domain 函数接到真实数据上：
1. 再平衡调整步骤：「未定义」资产的处理要按用户在设置里的选择（建议卖出 / 不参与）。
2. 投入一笔钱：两种模式（只在一个账户买 / 可跨账户），只推荐同币种的品种；每个槽位推荐已持有最多的那个品种。「按此记录买入」时，每个涉及的账户先各写一笔入金，再逐笔写买入。
3. 取钱：先卖超配最多的，只卖同币种的持仓；执行时逐笔写卖出，最后每个涉及的账户各写一笔出金。
4. 计划页的再平衡提醒：按阈值和检查周期判断，在 App 内提示。

用我的真实数据跑一遍，把「投入 ¥10 万」的建议结果列给我看，我来核对是否合理。
```

**验收**
- [ ] 投入 ¥10 万后，每个槽位买入后的占比都没有下降
- [ ] 取钱时只卖同币种的持仓
- [ ] 执行之后，持仓、现金、收益页的本金线都一致

## 阶段 6 · AI 投顾（DeepSeek）

**目标**：用自己的 Key 和 AI 讨论自己的组合。

**提示词**
```
按 README 实现 AI 投顾：
1. Key 加密后保存在本机：用 WebCrypto 加密，存进 IndexedDB，不要上传服务器。
2. 请求走 Worker 转发：新增 POST /ai/test（转发到 GET {base}/models）和 POST /ai/chat（转发到 /chat/completions，使用流式输出）。Worker 不记录 Key，也不记录对话内容。
3. 连接测试：按 401 / 402 / 超时分别给出明确的提示；必须勾选数据授权后才能开始对话。
4. 系统提示词：把计划、持仓、收益生成一段文字摘要，参考原型里 this._ctx 的格式；不包含账户号。
5. 会话和消息存进 Supabase（ai_conversations、ai_messages）；左上角抽屉里显示历史对话。
6. 「联网分析」开关：第一期先只在提示词里说明是否可以结合近期市场情况，真正的联网搜索留到以后做。
```

**验收**
- [ ] 填错 Key，提示 401
- [ ] 填对 Key，测试成功，回复以流式逐字显示
- [ ] 关掉 App 再打开，历史对话还在
- [ ] 在 Worker 的日志里看不到 Key
